# ROADMAP завершения MVP (после демо CTO)

## Этап 1: Интеграция реальных API (недели 1–2)
### Задачи
- [ ] Запросить у бэкенда контракты для `GET /api/v1/files` и `GET /api/v1/communications/threads`.
- [ ] Дождаться реализации эндпоинтов на сервере (или получить точные сроки).
- [ ] Обновить фронтенд: убрать моки из `src/lib/api/files.ts`, `src/lib/api/communications.ts` и из `src/lib/mocks/`.
- [ ] Переключить `NEXT_PUBLIC_USE_MOCKS=false` в `.env.production` и `.env.local` (для разработки можно оставить true до готовности бэкенда).
- [ ] Протестировать сценарий: загрузка файлов, получение списка потоков, отправка сообщений, обновление в реальном времени.
### Критерии приёмки
- [ ] В коде проекта нет ни одного мока (полное удаление).
- [ ] Приложение работает с реальным бэкендом без ошибок 4xx/5xx.
- [ ] Автотесты (unit + e2e) обновлены на реальные API или используют тестовый стенд.

## Этап 2: Деплой на staging (недели 1–2)
### Задачи
- [ ] Настроить деплой на Vercel (или Docker + k8s).
- [ ] Настроить переменные окружения для staging.
- [ ] Добавить e2e-тесты в CI (Playwright) с запуском на staging.
### Критерии приёмки
- [ ] Staging-ссылка доступна, приложение открывается.
- [ ] CI проходит: lint, type-check, unit, build, e2e.
- [ ] E2E-тесты стабильно проходят на staging (или на мок-сервере в CI).

## Этап 3: Завершение настроек (неделя 2)
### Задачи
- [ ] Реализовать раздел «Шаблоны»: сохранение шаблонов писем и сообщений, использование в коммуникациях.
- [ ] Реализовать раздел «Интеграции»: хранение API-ключей, тестирование подключений.
### Критерии приёмки
- [ ] Данные настроек сохраняются после перезагрузки страницы.
- [ ] Шаблоны доступны при отправке сообщений.

## Этап 4: WebSocket real-time (неделя 2–3)
### Задачи
- [ ] Подписать список тендеров на события `tender:status_changed`, `tender:updated`.
- [ ] Подписать список КП на `cp:received`.
- [ ] Подписать задачи на `task:progress`, `task:completed`.
- [ ] Инвалидировать кэш TanStack Query при получении событий.
### Критерии приёмки
- [ ] При изменении статуса тендера на бэкенде список тендеров обновляется автоматически без перезагрузки.
- [ ] При поступлении нового КП список КП обновляется.
- [ ] Прогресс задач отображается в реальном времени.

## Этап 5: Тесты и документация (неделя 3)
### Задачи

- [ ] Написать пользовательскую документацию (README, инструкция).
- [ ] Наполнить демо-данными тестовую среду.
### Критерии приёмки
- [ ] Покрытие ключевых сценариев e2e.
- [ ] Документация в репозитории.
- [ ] Демо-данные доступны для пилотной эксплуатации.
