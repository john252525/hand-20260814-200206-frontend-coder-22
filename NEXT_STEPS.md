# NEXT_STEPS.md — Конкретные шаги, сроки, ответственные

## Этап 1: Интеграция реальных API (недели 1–2, до 30.08.2026)

### Задачи
1. **Запросить у бэкенда контракты и реализации эндпоинтов:**
   - `GET /api/v1/files` — список файлов (с параметрами entity_type, entity_id при необходимости).
   - `GET /api/v1/communications/threads` — список потоков сообщений (с поиском и пагинацией).
2. **После получения API:**
   - В `src/lib/api/files.ts` изменить вызов: `apiClient.get('/api/v1/files')` без использования моков.
   - В `src/lib/api/communications.ts` изменить вызов: `apiClient.get('/api/v1/communications/threads')` без использования моков.
   - Установить `NEXT_PUBLIC_USE_MOCKS=false` в `.env.local` и `.env.production`.
   - **Проверить работу с реальным API:** загрузка и скачивание файлов, список потоков, отправка сообщений, real-time через WebSocket.
3. **После успешного тестирования:**
   - Удалить файлы моков: `src/lib/mocks/files.ts`, `src/lib/mocks/threads.ts`.
   - Удалить все упоминания `NEXT_PUBLIC_USE_MOCKS` из кода и переменных окружения.
4. **Обновить тесты:**
   - Unit-тесты не должны импортировать мок-данные.
   - E2E-тесты перевести на реальный API или на тестовый стенд (или оставить моки в `page.route()` для CI до стабилизации).

### Ответственные
- Frontend Developer — интеграция и удаление моков.
- Backend Developer — реализация эндпоинтов, согласование контрактов.
- QA Engineer (или Frontend Developer временно) — проверка сценариев, обновление тестов.

### Критерии готовности
- [ ] Приложение работает с реальным API без ошибок (при `NEXT_PUBLIC_USE_MOCKS=false`).
- [ ] В коде нет файлов моков и упоминаний `NEXT_PUBLIC_USE_MOCKS`.
- [ ] Unit-тесты обновлены.
- [ ] E2E-тесты либо используют реальный API, либо стабильно проходят с мок-роутами в CI.

## Этап 2: Деплой на staging (недели 1–2)
- Настроить Vercel project с переменными `NEXT_PUBLIC_API_URL` и `NEXT_PUBLIC_WS_URL` на staging backend.
- Добавить в Playwright `webServer` для запуска приложения на тестовом порту.
- В CI (GitHub Actions) подключить e2e с `webServer` и мок-роутами для стабильности.

## Этап 3: Завершение настроек (неделя 2)
- Реализовать сохранение шаблонов в разделе «Шаблоны».
- Реализовать сохранение и валидацию ключей в разделе «Интеграции».
